# Folder structure for a programme or research project

One structure, used from the first week, so that a file's location says what
it is and a new team member can find last year's endline without asking.

```
project_code/
  00_admin/            contracts, budgets, MoUs, approvals
  01_design/           proposal, theory of change, MEL framework, logframe
  02_instruments/      questionnaires by version, XLSForms, codebooks, consent forms
  03_data/
    raw/               exactly as received; never edited; read-only where the system allows
    clean/             produced from raw by a script in 05_code; can be deleted and regenerated
    external/          published data used alongside (census, NFHS, admin data), with source and date
  04_field/            training materials, field manuals, daily reports, back-check results
  05_code/             every script that turns raw into clean and clean into outputs
  06_outputs/
    tables/            generated, not hand-edited
    figures/
    reports/           drafts and finals, versioned by name (see file_naming_conventions.md)
  07_dissemination/    briefs, decks, press, published versions
  08_archive/          anything superseded, with a note saying by what
  README.md            what this project is, who runs it, where things are, what the codes mean
```

## The rules that make it work

**Raw data is never edited.** Anything wrong with it is fixed by a script in
`05_code/` that writes to `03_data/clean/`. The fix is then visible,
repeatable, and reversible. A hand-edited raw file is a raw file nobody can
trust and a change nobody can find.

**Everything in `06_outputs/` was generated by something in `05_code/`.** If a
table was made by hand in a spreadsheet, it lives in `08_archive/` with a
note, and a scripted version replaces it. This is the rule most often broken
and the one that makes a replication package (`../../replication/`) possible
at all.

**`03_data/external/` records where each file came from and when.** A census
table with no source and no date is a number with no provenance.

**The README is written in the first week and updated when the structure
changes.** It says what the project code means, who to ask, and where the
things are that are not obvious. `readme_template.md` is a starting point.

**Numbered top-level folders sort in workflow order**, which is the order a
newcomer needs them in.

## What goes where, when in doubt

| It is | It goes in |
|---|---|
| A questionnaire | `02_instruments/`, with a version in the file name |
| The CSV the platform exported | `03_data/raw/`, untouched |
| The script that cleaned it | `05_code/` |
| The cleaned file | `03_data/clean/`, regenerable |
| A chart | `06_outputs/figures/`, from a script |
| The report the chart is in | `06_outputs/reports/` |
| The two-page brief | `07_dissemination/` |
| Last year's version of the questionnaire | `02_instruments/`, older version number; or `08_archive/` if it will not be used again |
