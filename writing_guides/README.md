# writing_guides

Guides for the documents an evaluation produces, in the order they are
written.

| Guide | What it is for |
|---|---|
| `theory_of_change_notes.md` | The programme's theory as a short note: problem, pathway, assumptions, outcomes. `sample_theory_of_change_note.pdf` is a worked example; the `.qmd` is the same note as a Quarto source |
| `results_chain.md` | The theory with the arrows made explicit: "if A then B because C", one link at a time, to find the link everyone assumed |
| `evaluation_report_structure.md` | The report: what goes in which section, and the table of which verb each design permits in the summary |
| `policy_brief.md` | Two pages, one message, one ask, for a reader who decides things |
| `writing_about_uncertainty.md` | Sampling, design and measurement uncertainty, and how to write each in the same sentence as the number |

## The idea that runs through all five

The verb is decided by the design. "Rose among participants", "was higher
than in comparison areas", "increased relative to comparison areas",
"caused": these are not stylistic choices, they are claims of different
strength, and the design in the methods section fixes which one the summary
is allowed. Most misleading evaluation writing is a strong verb on a weak
design, and it usually happens in the summary or the brief, written last, by
someone who did not write the methods.

`../annotated_research/` has five reports read this way, with the verb
errors marked.
