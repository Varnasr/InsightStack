# tool_notes

Notes on nine visual, document and collaboration tools: when to use each,
when not to, and what goes wrong, with one example file per tool.

| Note | Tool | In the folder |
| --- | --- | --- |
| [`excalidraw_frameworks/`](excalidraw_frameworks/) | Excalidraw | Two editable diagrams, a MEL results chain and a district ecosystem map, with PNG previews |
| [`kumu_maps/`](kumu_maps/) | Kumu | A stakeholder map of a district health network as Kumu JSON, with a preview |
| [`observable_notebooks/`](observable_notebooks/) | Observable | An `.ojs` notebook plotting district coverage, its CSV, and a screenshot |
| [`open_data_editor/`](open_data_editor/) | RawGraphs, Datawrapper, Open Data Editor | A district indicators CSV shaped for those tools, and one chart |
| [`flourish_charts/`](flourish_charts/) | Flourish | The embed snippet and a screenshot |
| [`powerbi_reports/`](powerbi_reports/) | Power BI | An adaptation note and a screenshot; no `.pbix` ships |
| [`miro/`](miro/) | Miro | A design-session outline and links; no board ships |
| [`excel_visuals/`](excel_visuals/) | Excel | Three chart templates: bullet, waterfall, Gantt |
| [`latex/`](latex/) | LaTeX | A report skeleton that compiles with `pdflatex` |

Two points apply to all of them. These tools are quicker than code for a
first version and slower for the tenth, so a one-off workshop artefact
belongs in Miro or Excalidraw and a quarterly indicator chart belongs in
`ggplot2` or `matplotlib`. And Kumu, Flourish, Observable and Miro keep
files on their servers under their terms; Excalidraw and RawGraphs run in
the browser and keep nothing.
